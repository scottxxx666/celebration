# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
yarn dev       # start dev server (http://localhost:5173)
yarn build     # production build to dist/
yarn preview   # preview production build locally
yarn test      # unit tests (Node's built-in runner, no deps): tests/**/*.test.js
yarn test:tools  # Python unittest for the tools/ prep scripts (tests/tools/, via uv + Pillow)
yarn check:beats  # verify section + wave times sit on real track beats (--fix snaps off-grid section + wave times in place; runs before build)
```

Tests use `node --test` and live in `tests/`, so anything under test must stay importable in plain Node (no Phaser import, no browser globals at module top level).

## Architecture

**Stack:** Phaser 3 + Vite 6, vanilla JavaScript (ES modules).

**Scene lifecycle** (`src/main.js` bootstraps in order):
1. `BootScene` — asset loading; then `LanguageScene` on the first visit (no saved language), `WarningScene` on later loads, or straight to `MenuScene` under the `?t=` dev deep-link. Normal boot flow: `BootScene → [LanguageScene, first visit only] → WarningScene → MenuScene`
   - `LanguageScene` — language picker (see **Languages**): five rows, each language under its own name in its own font, nothing translated (only "Language" and a key-glyph hint), so it is usable by someone who cannot read the current language. Preselects the saved language, or the browser's on the first visit. Desktop ↑/↓ (W/S) or hover + SPACE/ENTER or click; mobile tap (rows fire only when the press began on them). Started with `{ next }` — `WarningScene` from boot, `MenuScene` from the menu's language row — and always pass it: a scene started without data keeps its previous data
   - `WarningScene` — photosensitivity warning (the game strobes, flashes and spins), shown on **every** page load and deliberately not remembered in localStorage; any key or a fresh tap (`onDismiss`) continues to `MenuScene`
2. `MenuScene` — title menu with Start, a difficulty row and a language row (third row, `menu.language`, always carrying the English word "Language" as well; confirming it — click/tap, or SPACE/ENTER while it is selected — opens `LanguageScene`, which returns here; SPACE/ENTER ignore auto-repeat so a key held from the previous scene can't start the game); the confirming gesture unlocks the browser audio context before gameplay starts (keeps music in sync). Start always goes to `HowToPlayScene` (see below), or straight to `GameScene` when the dev deep-link below is active. The bottom hint is device-aware (`device.os.desktop`: keyboard vs touch wording). The row under Start, `◀ Normal ▶` with the current difficulty's caption in a small grey line under it, cycles Easy/Normal/Hard (`src/difficulty.js`: `DIFFICULTY_IDS`, pure `parseDifficulty`/`stepDifficulty`, `getDifficulty`/`setDifficulty` — module cache over `celebration.difficulty` in localStorage, saved on every change): on desktop ←/→ (A/D) cycle it regardless of the selected row, and a click on the row cycles forward; on mobile tapping the row does. Cycling never starts the game; SPACE/ENTER starts it from either row (on the difficulty row it means "play this one"). On mobile each of the two rows is tapped through an invisible zone larger than its text (`menuRowLayout` in `src/menuLayout.js`: `MENU_TOUCH_WIDTH` wide, one row spacing tall so neighbours tile without overlapping, the difficulty zone extended down over its caption); desktop keeps the text itself as the hit target so hover selects only over the label. On desktop the selected row is marked by colour alone (white vs grey) — no cursor glyph, which would clash with the row's own `◀ ▶`. **Easy** = the player runs on `autoRun` (below); **Normal** is the default, unchanged; **Hard** swaps in `src/config/wavesHard.js` (`WAVES_HARD`). On mobile, the Start tap also requests fullscreen (guarded on `scale.fullscreen.available`, so iPhone no-ops) and attempts a landscape orientation lock on enter; on desktop, F toggles fullscreen in any scene (global DOM keydown listener in `src/main.js`, which also owns the mobile `enterfullscreen` → landscape-lock hook since fullscreen is game-global); every scene except `BootScene` also shows a top-right fullscreen button (`addFullscreenButton` in `src/objects/FullscreenButton.js`) that complements it — on desktop it's a clickable keycap-styled "[F] fullscreen" text label (no ⛶ icon) so keyboard players discover the shortcut (the desktop `HowToPlayScene` also lists it); on mobile it's the plain ⛶ expand icon — hidden entirely when the Fullscreen API is unavailable, taps `stopPropagation` so gameplay/skip/restart listeners never fire, and (in `GameScene`) rotates/zooms with the main camera during `rotate`/disco sections by design (no UI camera)
3. `IntroScene` — plays the intro video (`public/assets/intro.mp4`, encoding specs in `docs/video-assets.md`) in-canvas via a Phaser Video game object; SPACE/ESC/tap skips, and both skip and VIDEO_COMPLETE go through a guarded `startGame()` that waits for the audio unlock before starting `GameScene`. Sizing quirk: the Video object starts as a 256×256 placeholder and VIDEO_TEXTURE fires *before* Phaser adopts the real frame size, so the scene sets `setScale` from the event's texture dimensions — never `setDisplaySize`, which bakes in a 256-based scale that zoom-crops the video
4. `GameScene` — main gameplay loop; owns physics, scrolling background, collision detection, score, and music (starts on create, plays once — no loop). **Song = level**: the run is won when song time reaches `WIN_MS` (`gameConfig.js`, hand-tuned to 3 s after the last obstacle, slightly before the track's end — re-tune if `waves.js` is regenerated; `tests/winTime.test.js` fails if it falls before the last obstacle or inside a section), with the track's COMPLETE event as the fallback when `WIN_MS` lies past the end; a losing collision (chaser or obstacle) goes through `startCaught()`: the music stops, `update()` stops (the world freezes on the collision frame; `player.frozen` also blocks touch taps from stepping the sprite), flashes and a covering lights-out black are cleared, and `CAUGHT_FREEZE_MS` (2 s) later `endRun` starts `CaughtScene` with `{ won, score, progress }` (`runResult`, read before the music stops); a win first plays the **run-out** (`startRunOut()`, also the COMPLETE handler, guarded): `update()` stops reading the song clock, so the world freezes where it is (no scroll, no section effects, chaser and obstacles left in place, beat/strobe flashes cleared, music left to play out) while the runner — input ignored, run cycle handed back to its free-running timer (`RunCycle.freeRun`) — crosses the screen at `WIN_RUNOUT_SPEED` until `WIN_RUNOUT_PAD` px past the right edge (pure `runOutX`/`runOutDone` in `src/winRunOut.js`), then `endRun(true)` starts `EndingScene` with the same data. Dev/testing deep-link: `?t=` (seconds or `m:ss[.mmm]`, `src/songTime.js`, which also holds the HUD's `formatSongTime` so parse and format share one contract) seeks the music and fast-forwards the spawner (`ObstacleSpawner.skipTo`) to start the run partway through the song; everything else already derives from `conductor.songMs` so it needs no special-casing, and restarting from `GameOverScene` naturally resumes at the same start time since `GameScene` reads the URL itself rather than via `init(data)`. A second dev flag, `?debug` (`src/debugMode.js`, composes with `?t=`), pins `Player.speed` at `ENEMY_CRUISE_SPEED` — taps and deceleration are ignored — so the chaser never closes in and a run can be played through without tapping
5. `EndingScene` — ending cutscene after a won run (`GameScene → EndingScene → GameOverScene`; a lost run goes through `CaughtScene` instead): plays the `ending` video in-canvas with the same setup as `IntroScene` (**placeholder: `BootScene` loads `assets/intro.mp4` under the `ending` key until a real `ending.mp4` exists**), with the `ending.message` line centred over it from the first frame; `ENDING_CONTINUED_DELAY_MS` (2 s) later `ending.toBeContinued` appears bottom-right together with the skip hint, and only then is the skip (SPACE/ESC/tap, `onDismiss`) armed — the player is still mashing run taps when the run is won, and those must not skip the ending. Skip or VIDEO_COMPLETE goes on to `GameOverScene` with the run's `{ won, score, progress }`
6. `CaughtScene` — shown after a lost run (`GameScene → CaughtScene → GameOverScene`): the static `CAUGHT_IMAGE` (`public/assets/caught.jpg`, authored at 2x, preloaded by `BootScene`) with the `caught.message` line over it, silent; goes on to `GameOverScene` with the run's data by itself after `CAUGHT_IMAGE_MS` (3 s), or on SPACE/ESC/tap (`onDismiss`), armed only after `CAUGHT_SKIP_ARM_MS` so leftover run taps can't skip it
7. `GameOverScene` — shows CLEAR! (win) or GAME OVER plus song progress %, survived seconds and the difficulty played, with two tappable/clickable labels on every device — `Restart` (→ `GameScene`) and `Menu` (→ `MenuScene`, the only way to change difficulty) — and on desktop the same white/grey selection as `MenuScene`: ↑/↓ (W/S) or hover moves it, SPACE/ENTER confirms, `Restart` is preselected so one SPACE still retries, and ESC always goes to the menu. Selection keys ignore auto-repeat and the first `SELECT_GRACE_MS`, since ↑/↓ are gameplay keys a player may be mashing at the moment of death. There is deliberately no tap-anywhere restart: a label fires only when the press began on it (`addButton`), so a finger held from the death tap can't spend it. Under Menu sits a small pointer-only **share row** of three brand icons — X, Threads, Instagram (`SHARE_ICONS`: Simple Icons SVGs in `public/assets/icons/` in brand colours — X and Threads white, Instagram its gradient — rasterised by `BootScene` via `load.svg`, slightly dimmed by a tint and brightened on desktop hover; no caption; not in the ↑/↓ keyboard selection; `armTap` gives them the same press-began-here rule as `addButton`). Pure text/link building lives in `src/share.js` (`shareText` through the i18n tables, `shareLink` for the X / Threads intent URLs; the game link `SHARE_URL` in `gameConfig.js` rides inside `text` since only `text` is reliably honoured); X and Threads `window.open` in the pointerup handler. `IG Story` has no web share URL, so it shares a PNG screenshot: on touch devices `navigator.share({ files })` when `canShare` allows it, otherwise (desktop) it downloads `celebration.png` and shows the `share.saved` notice. The screenshot (`renderer.snapshot`) is **pre-captured** `SNAPSHOT_DELAY_MS` after the scene starts (so texts and a win's confetti are in frame) and stored as a Blob, because `navigator.share` needs the tap's user activation and would not survive an async capture started on tap (a tap that beats the pre-capture captures then, as a fallback). On a win it fires a one-shot confetti-cannon pop (`Confetti` in `src/objects/Confetti.js`) to celebrate — pooled `add.rectangle` pieces launched up-and-inward from the bottom corners, falling under gravity with horizontal air drag, tumbling (spin + a scaleX flip fakes edge-on paper) and fluttering (sinusoidal sway), fading out near end of life (`CONFETTI_*` in `gameConfig.js`), depth 9, purely visual

`HowToPlayScene` — full-screen instructions, shown only as a **gate on every Start** that `MenuScene` inserts between Start and the intro video (there is no separate menu entry — every Start shows it anyway), making the flow `MenuScene → HowToPlayScene → IntroScene → GameScene`. It is deliberately not remembered in localStorage: the screen's content depends on the difficulty (Easy auto-runs), so a saved "already seen" would go stale when the player switches; `GameOverScene`'s `Restart` skips it by going straight to `GameScene`. Every exit goes on to `IntroScene`, so ESC is "skip ahead" like the other keys, matching `IntroScene`. The input that confirmed Start must not also dismiss the gate before it can be read — keys ignore auto-repeat (SPACE held down) and the pointer requires a fresh press/release, the same hazard `GameOverScene` guards against. Device-aware (`device.os.desktop`): desktop shows two keycap-demo columns (←/→ and ↑/↓ press animations); mobile shows a single **landscape** phone mock mirroring the real play screen, running a sequenced play loop on one 350ms clock — six alternating finger taps on the left/right halves, then one thumb-side swipe (up on the right half, down on the left — alternating halves says "swipe anywhere works"; the divider dims during it and a chevron pulses beside the swiping half), then a rest tick — with all captions stacked full-width below (the long monospace lines overlap in a two-column layout). On Easy (`getDifficulty()`, already chosen by the time the gate shows) the run caption says the player runs automatically; the desktop run demo is dropped (the rows column takes the centre and the run caption joins the full-width lines below), while the mobile mock drops the taps and the tap-halves divider entirely and loops the swipe alone (tick sequence is the pure `mobileDemoAction` in `src/howToPlayDemo.js`). The desktop column captions are two lines each — on one line they are wider than the column spacing and collide. Any key or tap continues to `IntroScene`.

**Game objects** (`src/objects/`):
- `Player` — `new Player(scene, x, { autoRun })`: `autoRun` pins speed at `ENEMY_CRUISE_SPEED`, ignores taps/deceleration and keeps the beat-locked run cycle (`tapIdleMs: 0`); `GameScene` sets it for `?debug` or Easy difficulty. Alternating left/right key taps accelerate the player; up/down arrows snap between 3 rows. WASD aliases the arrows everywhere (gameplay and menu) via `addDirectionKeys`/`anyJustDown`/`onDirectionKey` in `src/input.js`. Input is split into shared methods — `tap(side)` (alternating accel) and `moveRow(dir)` (clamped row snap) — so keyboard (`update()`) and touch share one code path. Touch controls (`Player.attachTouch(scene)`, called by `GameScene`): tapping the left/right half of the screen calls `tap()` on `pointerdown`; a vertical swipe past `SWIPE_THRESHOLD` (`gameConfig.js`) calls `moveRow()` mid-gesture, one row change per pointer until release — tracked per-pointer so two-thumb tapping and a swipe don't interfere. When `PLAYER_FRAME_COUNT` (`gameConfig.js`) is non-zero, the green rectangle is replaced with run-cycle frames via the shared `RunCycle` helper (`src/objects/RunCycle.js`, frames from `src/config/runFrames.js`, prepped by `tools/prep-run-frames.py`, `--dummy` generates placeholder frames before real art exists); each frame once the beat clock runs `GameScene` calls `syncFrame(conductor.gridIndex(PLAYER_RUN_STEPS_PER_BEAT × section.speedMult))` (6 steps per game beat, so the 6-frame two-step cycle lands a foot contact — frames 0 and 3 — every half game beat; the enemy has its own `ENEMY_RUN_STEPS_PER_BEAT`, 8th notes), which shows frame `walkIndex % frameCount` (never double-steps; the beat grid fixes the phase, so `?t=` seeks land on the right phase) — while a free-running timer in `RunCycle.update()` at the same per-character rate (`BEAT_MS / stepsPerBeat`) only animates the walk before the first sync, so the player walks from the first frame even before the first downbeat / audio start, and is silenced once beat-locked — while the `pulse()` beat squash still waits for `BEAT_SYNC_START_MS`; falls back to the plain rectangle when the count is 0. **That beat-locked cycle is the player's idle fallback**: with `PLAYER_TAP_RUN_IDLE_MS` non-zero (the default) the player's run is tap-driven while the user taps — each accelerating tap in `tap()` calls `runCycle.step()`, advancing exactly one frame and holding it (`syncFrame()` and the timer are ignored) so feet follow the fingers; once that long passes without a tap, and before the first tap, the beat-locked cycle runs again so the character never freezes. `?debug` (taps ignored) and a value of 0 keep the beat-locked cycle only
- `ObstacleSpawner` — spawns the authored waves (`new ObstacleSpawner(scene, waves = WAVES)`; `GameScene` passes `WAVES_HARD` on Hard) from `src/config/waves.js`, timed off song time (passed in from the Conductor) so obstacles arrive at the player on the beat; scroll speed is the player's actual speed, while spawn timing uses a separate `timingSpeed`. The authored waves are flattened once in the constructor into an arrival-sorted `pending` list with a spawn cursor (`next`), so the per-frame scan only covers the lookahead window. Each obstacle gets a deterministic character sprite from `src/config/obstacleSprites.js` (`spriteFor`, avoiding a same-wave repeat), rendered origin `(0,1)` so its left edge and feet line match the sprite's `hw` and shadow (`docs/image-assets.md` "Obstacle character sprites"); the collision box is narrower than the art — `hw × OBSTACLE_HITBOX_SCALE` (`gameConfig.js`), shrunk around the same centre, collision only (art, shadow and spawn timing keep the full `hw`); falls back to the old placeholder rectangle if no sprites are configured
- `Enemy` — chases from the left; its speed ramps from `ENEMY_SPEED` to `ENEMY_CRUISE_SPEED` anchored to song time, pinning the player into a narrow speed band near max. Tracks the player's row instantly during the intro; once beat sync is on it steps onto the row only on beat crossings, so row-dodging buys up to one beat of separation. Uses the same `RunCycle` helper as `Player` for its visual, with its own `ENEMY_FRAME_COUNT`/`ENEMY_SPRITE_HH` frame set; `GameScene` calls `syncFrame()`/`pulse()` on both the player and the enemy together — each walks at its own `*_RUN_STEPS_PER_BEAT` rate off the same beat grid, and they bounce in lockstep
- `SpinBikes` — `new SpinBikes(scene, conductor)`: a row of `BIKE_COUNT` front-facing (toward the camera, symmetric) cel-shaded riders (tapered outlined limbs with round joints, oval head with ears, tank/shorts/sneakers/hair per rider from the `BIKE_SKINS`/`BIKE_TOPS`/`BIKE_SHORTS`/`BIKE_HAIR` palettes) on dark stationary spin bikes (floor stabiliser, edge-on flywheel, post, handlebar) with an accent rim light (`BIKE_COLORS`, `BIKE_RIM_ALPHA`), drawn each frame with an invisible Phaser Graphics at `BIKE_RENDER_SCALE`× into a RenderTexture (strip of the scenery height, `STRIP_MARGIN` px past each screen edge) shown scaled back down for smooth edges (no image assets; every part is an outline underlay in `BIKE_OUTLINE_COLOR` then fills with a `shade()` shadow side, light from the upper left), at depth `BIKE_DEPTH` (−9.5, between the scenery strip and the dim overlay). `GameScene` calls `update(section, songMs, worldDx)` right after `scenery.scroll`: the row enters at the right edge on a `bikes` section's first frame (`bikeRowStartX` estimates the x for `?t=` seeks), then accumulates `worldDx × SCENERY_PARALLAX` so it drifts with the backdrop, and keeps drifting after the section ends until its right edge is off-screen left, then hides (`finished` blocks re-entry until a non-bikes frame). Pose is stateless from the beat grid (`conductor.phaseMs`): crank turns once per `BIKE_PEDAL_BEATS`, each leg a 2-bone IK (`legIK`) solved in the sagittal plane from hip to pedal and projected to the screen by `frontLeg` (y kept, knee splayed outward by `BIKE_SPLAY` × forward depth; legs half a turn apart), arms raised and waving on the beat grid (`armLean`/`armPose`): every rider in unison snaps within `BIKE_ARM_HIT_FRAC` of the wave period (1/`BIKE_WAVE_HITS_PER_BEAT` beat; 2 = every half beat) after each hit to a lean toward screen-right on even hits / screen-left on odd (both straight arms stay parallel, pointing straight up between hits, and swing together, toward the front at azimuth `BIKE_ARM_FORWARD_DEG` and projected like the legs so they foreshorten, with the fist scaled by depth via `BIKE_ARM_HAND_DEPTH_SCALE`) (`conductor.gridIndex(BIKE_WAVE_HITS_PER_BEAT)` parity), overshoots the pose by `BIKE_ARM_OVERSHOOT` and settles back over `BIKE_ARM_SETTLE_FRAC`, holds `BIKE_ARM_HOLD_FRAC` of the period, relaxes to `BIKE_ARM_RELAX` of the lean, then rests there (straight up) for the last `BIKE_ARM_REST_FRAC` of the period before the next hit; pedalling is in unison too. Mode `'grip'` instead keeps both hands on the bar ends (`gripArm`: `legIK` elbow flared outward) while shoulders sit `BIKE_GRIP_HUNCH_PX` low (rising `BIKE_SHOULDER_BOB_PX` at a full nod) and the head nods (`headNod(gripDip)`: sinks `BIKE_NOD_DROP_PX`, the hair/cap edge slides down the head so the crown shows and the eyes hide, `BIKE_NOD_*`) — fully down for `BIKE_DIP_HIT_MS` on each beat, back up by mid-beat. Ponytail/bun swing (`BIKE_HAIR_SWING_PX`) replays the nod / arm lean `BIKE_HAIR_LAG_MS` late (`laggedBeat`). Pure maths in `src/spinBikes.js`
- `Scenery` — the road + background scenery strip, a themed pair from the `SCENERY_THEMES` table (`src/config/sceneryThemes.js`), chosen by song-time **stages** (`src/config/stages.js`: `STAGES` `{ name, startMs, theme }`, pure `stageAt(songMs)`; `suburb` → `suburbDay` → `desert` (AI backdrop over a procedural layout + road, `tools/gen-desert-assets.py`, from 53156 ms) → `underground` (dim tiled underpass, procedural road + scenery, `tools/gen-underground-assets.py`, from 59134 ms) → `concert` (AI restyle of a procedural stage layout + procedural road, glow and crowd layers, `tools/gen-concert-assets.py`, from 63518 ms, flanked by two `crowdOnly` windows from 59931 ms and 86235 ms — 9 beats before it starts/ends, i.e. `STAGE_FADE_BEATS` of fade then the rest held — the concert's sky/road/ground/crowd over the fully transparent `scenery-blank.png` with no glow, so only the swaying crowd shows, under a grey-green mask (theme `dim` + `dimColor`, black when omitted: `Scenery.dimMask` at depth −9.84 over road, scenery and crowd, alpha from the pure `themeDim(from, to, t)` in `sceneryThemes.js` so it fades with the stage blend) that darkens the concert road's purple; `Scenery.updateCrowd` keeps the shared crowd at full alpha through a fade between themes sharing one `crowd` array so it doesn't dip; `sky` 0x000103; lit lamp lenses dimmed and their haze neutralised by `tools/prep-concert-lamps.py`, which also saves the lit lens patches `tools/ref/concert-lamps-lit.png` that `gen-concert-assets.py` turns into the real-lens glow, so the pulse glow relights them) → placeholders reusing existing themes): a theme may carry an optional `tint` (0xRRGGBB, omitted = unchanged; `suburbDay` darkens its light art) multiplied onto its strips via `setTint` and onto its sky/ground fills via `multiplyColor`, applied per layer set so it crossfades with it; `Scenery` is built with `stageAt(getStartMs())`'s theme and `GameScene` calls `scenery.setBlend(...stageBlend(songMs, STAGE_FADE_BEATS * BEAT_MS))` every frame — the pure `stageBlend` (`src/config/stages.js`) returns `{ from, to, t }`: a stage change crossfades over `STAGE_FADE_BEATS` (`gameConfig.js`, 4 beats; 0 = hard cut) starting at the stage's `startMs`, previous theme into the new one, with `t = 1` and `from === to` otherwise (the first stage never fades). A stage with `cut: true` skips the fade and hard-cuts at its `startMs` (`stage4`, under the `WallBreak` flash). `Scenery` keeps two identical layer sets (strips/fills at −10/−11 for the base showing `from`; an overlay at −9.9/−10.9 showing `to` at alpha `t`, hidden once settled so there is no double draw), only calling `setTexture`/`setFillStyle` when a set's theme changes, and `scroll()` advances both sets together; stateless from song time so `?t=` seeks just work. `BootScene` preloads every theme used in `STAGES`; stage times must sit on a real track beat, which `yarn check:beats` verifies (report only, startMs 0 exempt). A theme may also carry an optional `flicker` ({ key, file }, preloaded by `BootScene`): an RGBA glow image (one plain `Image`, depth −9.95 between the base and overlay strips, tinted like the base theme) that `GameScene` drives every frame with `scenery.setFlicker(lampFlicker(songMs, BEAT_MS))` before `setBlend`/`scroll`. The strip tiles every texture width, but only ONE copy of the lamp flickers: when the stage is settled and the level first goes above 0, the pure `firstCopyFromRight` (`src/lampFlicker.js`, using the theme's `flicker.lampX` in texture px) picks the first copy whose lamp is just off the right edge, and `scroll()` pins the image to that copy (`copyScreenX`, from the strip's `tilePositionX`) so it enters from the right once and drifts off left while later copies stay dead (the choice resets when the base theme changes). Alpha is the level, forced to 0 for the whole stage crossfade (the glow is one theme's lit art behind a hard-edged mask, so over a half-faded mix it shows as a patch). The pure, stateless `lampFlicker` (`src/lampFlicker.js`, tuned by `LAMP_FLICKER_*` in `gameConfig.js`) models a dying tube: mostly dark, burst beats of rapid on/off slots, rare dim blips; `underground` uses it to light its dead lamp (`make_flicker` in `tools/gen-underground-assets.py`). A theme may also carry `crowd` (`[{ key, file }, { key, file }]`, preloaded by `BootScene`; only `concert`): two transparent crowd-silhouette frames (`tools/gen-concert-assets.py`; the base scenery has no crowd so the stage art can be restyled) that `Scenery` draws as one `tileSprite` locked to the scenery's `tilePositionX` at depth −9.85 (over the base, pulse glow and crossfade overlay so people occlude the light behind them; under SpinBikes, the dim and every row). `GameScene` calls `scenery.setCrowdFrame(crowdFrame(conductor.beatTimeMs, BEAT_MS, CROWD_SWAPS_PER_BEAT))`; the pure `crowdFrame` (`src/crowdSway.js`, floor/mod safe, `CROWD_SWAPS_PER_BEAT` 0 pins frame 0) alternates 0/1 every 1/N beat, neighbours being in opposite poses so the crowd ripples. The crowd follows its theme through a crossfade (alpha t as the incoming theme, 1 − t as the outgoing one, full when settled). A theme may also carry `pulse` (`[{ key, file, group }]`, preloaded by `BootScene`; only `concert`): additive glow images (lamp halos/lenses per colour group + the LED wall, `tools/gen-concert-assets.py`) that `Scenery` draws as ADD-blend `tileSprite`s locked to the scenery's `tilePositionX` (depth −9.95, so EVERY tile copy pulses, unlike `flicker`), plus a whole-strip additive brightness-lift rectangle (−9.96, `PULSE_LIFT_COLOR`) under them. `GameScene` calls `scenery.setPulse(beatPulse(conductor.beatTimeMs, BEAT_MS))` every frame; the pure `beatPulse` (`src/beatPulse.js`, stateless so `?t=` seeks and negative times just work, tuned by `PULSE_*` in `gameConfig.js`) returns `{ lift, groups }`: each `PULSE_GROUPS` entry fires on beat-grid slots with `slot mod every === offset` (`divisions` per beat; default magenta on even beats, cyan on odd, wall every half beat) and ease-outs over `decay` slots, scaled by `PULSE_GLOW_STRENGTH`; the lift is `PULSE_LIFT_STRENGTH` fading over `PULSE_LIFT_DECAY_BEATS` each beat; a strength of 0 disables that layer. `Scenery.updatePulse` shows them only while the settled base theme owns them (zero during a crossfade like `flicker`; gated on stage song time, independent of `BEAT_SYNC_START_MS`); they sit below the dim overlay, so dimmed sections darken them. Both layers are `tileSprite`s (`setTileScale(0.5, 0.5)` since the art is authored at 2× logical size) oversized in x to cover the circle the `rotate` section's zoomed-out, spinning camera sweeps, with flat-colour sky/ground rectangles filling in beyond that; `scroll(dxWorldPx)` advances the road's `tilePositionX` and the scenery's at `SCENERY_PARALLAX` (`gameConfig.js`, 0.2) of that, so the backdrop drifts slower than the road and reads as further away (0 = static). **Languages** (`src/i18n.js`, strings in `src/config/strings.js`): English, Korean, Japanese, Simplified and Traditional Chinese (`LANGUAGES`, ids `en`/`ko`/`ja`/`zh-Hans`/`zh-Hant`, in picker order). Every player-facing string is a flat key in `STRINGS[lang]` read through `t(key, params)` (`{name}` placeholders; falls back to English, then the key) — never inline a literal in a scene; the title "CELEBRATION", key glyphs and the debug HUD are the only untranslated text. `en` is the reference table: `tests/i18n.test.js` fails when a language misses/adds a key, drops a placeholder, or changes the line count of a multi-line string. Line breaks are authored (`\n`), not wrapped — CJK has no spaces. The choice lives in a module cache over `celebration.language` in localStorage (`getLanguage`/`setLanguage`, like `difficulty.js`); until the player picks, `getLanguage()` returns the pure `detectLanguage(navigator.languages)` guess and `hasChosenLanguage()` is false, which is what makes `BootScene` show the picker. Fonts are system fonts, one stack per language (`LANGUAGES[id].font`, CJK languages list their own regional fonts first because Han code points are shared but drawn differently; English keeps Phaser's default Courier so its layouts are unchanged): every translated `add.text` wraps its style in `textStyle(style, lang?)` from `src/config/ui.js`. Scenes build their texts in `create()`, so a language change takes effect by (re)starting the scene — no live relabelling. `syncDocument()` keeps `<html lang>` and index.html's portrait rotate overlay in step (called from `main.js` and `setLanguage`). Difficulty labels/captions are the `difficulty.<id>` / `difficulty.<id>.caption` strings (`DIFFICULTY_IDS` in `src/difficulty.js`).

**Shared UI/input helpers**: `src/config/ui.js` holds the keycap palette, the top-right HUD row constants (`HUD_*`, `hudPart()`), `addKeycap()`, the `TITLE_STYLE`/`CAPTION_STYLE`/`HINT_STYLE` text styles, `textStyle()` (see **Languages**), and `isDesktop(scene)`. `src/input.js` holds `bindPointer(scene, {down, move, up})` (scene-level pointer listeners with SHUTDOWN teardown; `up` also covers `POINTER_UP_OUTSIDE`) and `onDismiss(scene, {keys, tap})` — the "any input moves on" gate used by `IntroScene`, `HowToPlayScene` and `GameOverScene` (keys only there — its taps go to the two labels), which ignores key auto-repeat and requires a fresh press-then-release tap.

**Audio volume**: sources play at full loudness; the user volume alone sets loudness, defaulting to `DEFAULT_VOLUME` (`gameConfig.js`, 0.6) when nothing is saved — a saved value wins, and the slider's max (100%) is louder than the default. The user volume lives on the game-global sound manager, seeded from localStorage (`celebration.volume`) by `BootScene`, but **reads go through the cache in `src/userVolume.js`** (`getUserVolume`/`setUserVolume`/`saveUserVolume`) — reading `scene.sound.volume` back is stale while the audio context is still locked (WebAudio `gain.setValueAtTime` isn't reflected by `gain.value` until resume), which is the pre-gesture state in early scenes. It's driven by a draggable slider (`addVolumeSlider` in `src/objects/VolumeSlider.js`) shown top-right only in the two audio scenes — `IntroScene` (video) and `GameScene` (music) — on the same top row as the fullscreen button, immediately left of it (`addFullscreenButton` returns the x where the next widget's right edge belongs, so the row packs right-to-left and the slider takes the corner on iPhone where the button is absent — call the button first); the slider's speaker icon lights up 0–3 wave arcs with the level as a readout. The slider stopPropagates its zone's pointerdown/pointerup like the fullscreen button, and tracks drags manually per `pointer.id` at scene level (using `pointer.worldX`, so it keeps working while the GameScene camera rotates/zooms); because stopPropagation also cancels the scene-level `POINTER_UP`, drag end is handled in the zone's own pointerup too, with stale-drag guards on move (`!pointer.isDown`) and on a scene-level down reusing the id. Volume is saved on drag end (and on shutdown mid-drag). Music inherits the manager volume automatically (final = manager × sound volume); the intro video does **not** go through the sound manager, so `IntroScene` applies the user volume directly and re-applies on `GLOBAL_VOLUME` (listener removed on shutdown — the manager is game-global). `IntroScene`'s tap-skip arms on pointerdown (like `GameOverScene`'s restart) so a slider drag released off-zone can't skip.

**Beat clock** (`src/Conductor.js`): minimal music clock (`BPM` + `FIRST_BEAT_OFFSET_MS` from config); polled each frame by `GameScene` for beat/half-beat crossings, and the single read point for song time (`conductor.songMs`) **and beat-grid math** (`beatTimeMs`, `gridIndex(divisionsPerBeat)`, `phaseMs(periodBeats)` — the strobe and zoom punch use these — plus the pure `snapToTrackBeat(ms)`/`trackBeatOf(ms)` used by the offline beat checker; nothing outside it knows `FIRST_BEAT_OFFSET_MS`). `songMs` is the *heard* position: `music.seek` minus the audio output latency, auto-detected each frame from the WebAudio context (`baseLatency + outputLatency`, with a 10 ms hysteresis so a wobbling estimate doesn't jitter the clock; 0 without a context) plus the manual `AUDIO_LATENCY_OFFSET_MS` trim (`gameConfig.js`, positive = visuals later) — the adopted total is `conductor.latencyMs`, nothing else knows about latency, and `songMs` therefore starts a run slightly negative. Score, the beat-sync gate, the enemy ramp, and obstacle spawning all run on it; nothing else reads `music.seek`. The whole beat-sync layer — enemy row-stepping, the player's 8th-note squash pulse, and the walk-zone beat flash — switches on together at `BEAT_SYNC_START_MS` (song time, independent of the enemy speed ramp); before that the game behaves like the original intro.

**Speed/rhythm design** (`docs/speed-design.md`): from `OBSTACLE_TIMING_SWITCH_MS` (song time, its own knob — set to when the enemy ramp completes), obstacle spawn timing assumes the band average (`OBSTACLE_TIMING_SPEED`) instead of the instantaneous player speed, keeping on-beat arrival within ~±40ms. Before that (sparse intro), timing uses the player's actual speed.

**Configuration** (`src/config/gameConfig.js`): single source of truth for canvas size, speed bounds, acceleration/deceleration rates, enemy ramp, and music constants (`BPM`, `FIRST_BEAT_OFFSET_MS` — measured from the real track: 150.55 BPM; `BPM` = `TRACK_BPM` by default, one game beat per real track beat; the half-time alternative is commented beside it, and `sections.js` `strobe`/`lightsOut` values are authored for the default). Tune gameplay here, not inline. Wave/beat maps live in `src/config/waves.js`, which is GENERATED from the track's onsets by `tools/gen-waves.py` (each obstacle's `timeOffset` is in **real track beats** after its wave's `songTime` (ms) — `ObstacleSpawner` converts with `TRACK_BEAT_MS`; section table + density profiles live in the script; regenerate with `uv run --with librosa --with numpy python tools/gen-waves.py`, never hand-edit; `src/config/wavesHard.js` is the Hard chart, a frozen snapshot of waves.js at commit 656c753 that gen-waves.py does not regenerate — its only edit since is dropping the pair inside the wall-clear window (`WALL_CLEAR_BEATS`, see `StationBuilding`), made by hand; the committed waves.js also carries hand-tuned waves the generator does not reproduce, so diff a regeneration before keeping it (the same wall-clear drop was applied to it by hand); `yarn check:beats`, run as `prebuild`, fails if any wave time (either chart) drifts off a real beat, and `tests/winTime.test.js` checks `WIN_MS` against both charts; `--fix` snaps off-grid waves.js times in place (wavesHard.js is report-only), but regenerating overwrites such edits); the `wall` profile (chorus 2, final chorus) emits a two-obstacle wall with one gap row every two track beats, the gap stepping ±1 row per wall, which forces one on-beat row move per beat without any player-side quantization.

**Song sections** (`src/config/sections.js`): authored, song-time-anchored spans (like `waves.js`) that layer effects on top of normal play; `sectionAt(songMs)` returns the containing section or a normal default. `speedMult` is a global world multiplier `GameScene` applies to background scroll, obstacle scroll/spawn timing, and enemy motion, and the walk cycle's frame rate (not `Player.speed` — taps feel the same, only the world moves faster); the old `disco` flag is split into two independent per-section fields, `dim` and `lights`, so a section can be dark only (rows wanting both spread the `DISCO` preset in `sections.js`, which also turns on `zoomPunch`); `lights` shows `DiscoLights` top-down beam cones (plus pools and lasers) that jump to a random position/slant on every beat, each taking a distinct colour from `DISCO_COLORS` offset by its element index (a "palette spread", never random) — the whole set advances together per bar (`DISCO_HUE_BEATS`), and the beat-flash overlay uses the base hue; each beam also fakes volumetric haze with nested narrower/brighter inner-cone triangles (`HAZE_INNER_WIDTH_RATIOS`/`HAZE_INNER_ALPHA`) and a soft apex glow blob at its source (`HAZE_APEX_GLOW_WIDTH`/`HAZE_APEX_GLOW_HEIGHT`/`HAZE_APEX_GLOW_ALPHA`), both sharing the parent beam's apex/axis/colour and re-jumping in lockstep with it — and `dim` fades in a black overlay (depth −6, between the background and the lights/beat overlay) that darkens the world so the beams pop without dimming the player/enemy/obstacles above it — fading in/out on a beat-aligned ramp (`DISCO_DIM_FADE_MS`) at the start/end of the contiguous dimmed span — back-to-back dimmed sections fade as one (`dimStartMs`/`dimEndMs`, precomputed in `sections.js`); a per-section `strobe` field (flashes per beat — its own authored effect, independent of `dim`/`lights`; may instead be a list of `[beats, rate]` steps from the section start, `strobeRate` in `sections.js`, which `ready` uses to build from slow to fast) flashes full-screen white (`this.strobeOverlay`, depth 8, above gameplay) to `STROBE_ALPHA`, fading over `STROBE_DECAY`, aligned to the beat grid and gated purely on section song-time; an optional per-section `strobeRamp` (fraction of `STROBE_ALPHA` at the section start, rising linearly to full at the section end; `strobeScale` in `sections.js`; `ready` uses both, to build with the track) scales that flash's peak; a per-section `lightsOut` field (`{ lit, dark }` in beats, cycling from the section start: lit for `lit` beats first, then dark for `dark` beats; optional `bursts` + `gap` repeat the lit part as `bursts` short blinks with `gap` beats of dark between them before the long `dark`; `null` = off) covers the screen with a full-black overlay (`this.lightsOutOverlay`, depth 9, above gameplay and the strobe, below the HUD) for the dark part of each cycle, fading in over `LIGHTS_OUT_FADE_MS` and snapping back on — it hides obstacles, player and chaser entirely; an optional `reveal` in that object keeps something readable through the dark part: `'shadows'` turns every drop shadow into a light ellipse lifted above the overlay (`styleShadow` in `src/rowLayout.js`, `LIGHTS_OUT_SHADOW_*`), `'silhouettes'` (what the first `blackout` section uses) drops the overlay behind gameplay (depth −1) as a near-black backdrop (`LIGHTS_OUT_SILHOUETTE_BG`) and tints the sprites solid black (`styleSilhouette`) — both driven by `setReveal` on `Player`/`Enemy` and `spawner.reveal`; an optional `strobe: true` there fires the white strobe flash (`LIGHTS_OUT_STROBE_ALPHA`/`STROBE_DECAY`, same overlay as the section `strobe`) each time the lit part begins, so the lights read as strobing back on — without a `reveal`, that section's obstacles must be authored to arrive while lit or right as the dark begins; `rotate` continuously spins the main camera (at `ROTATE_BEATS_PER_TURN` beats per revolution, zoomed to `ROTATE_ZOOM` so the whole field stays visible) anchored to the section start — half a turn counterclockwise (to upside-down), then the same half turn back clockwise, alternating every half turn (`rotateTurns` in `sections.js`; `final_highlight` is exactly one out-and-back swing, reversing at its halfway point, so it ends upright) — purely visual; a per-section `ghost` boolean ("double vision") has `GameScene` draw the whole world extra times through `GHOST_COUNT` additional translucent cameras (added last in `create()`, `inputEnabled = false` so hit-testing/`pointer.worldX` stay on the main camera; they `ignore` the HUD — the debug `speedText` plus every scene child at `HUD_DEPTH` or above, which is exactly what the volume slider and fullscreen button create), each copying the main camera's rotation/zoom and offset by `ghostOffset(i, count, phase)` — an ellipse orbit once per `GHOST_SWAY_BEATS` (`GHOST_OFFSET_X/Y`, slightly larger zoom per index `GHOST_ZOOM_STEP`) — at `GHOST_ALPHA × ghostFade(section, songMs, beatMs)` — the effect pulses rather than holding: from the section start it is ghosted for `GHOST_ON_BEATS` beats, then clear for `GHOST_OFF_BEATS`, repeating, with linear `GHOST_FADE_MS` ramps at both edges of each pulse (and before the section end); both pure functions live in `src/ghostWorld.js`, composes with `rotate` and the zoom punch, stateless from song time, and is not meant for `lightsOut` sections (the copies would show through the black overlay); a per-section `trails` boolean (its own flag, independent of `ghost`) has the player, the chaser and every obstacle leave afterimages: `Afterimages` (`src/objects/Afterimages.js`, owned by `GameScene`, created before the ghost cameras so its pooled images are drawn by them too) drops one tinted silhouette copy of each textured source image every `TRAIL_STAMP_MS` (all stamps of a round share a colour cycled from `TRAIL_COLORS`; placeholder rectangles are skipped by an `instanceof Phaser.GameObjects.Image` check), at depth `TRAIL_DEPTH_OFFSET` behind its source, and fades each over `TRAIL_LIFE_MS` (`trailAlpha`/`trailColor` in `src/trails.js`); stamps slide left at `TRAIL_DRIFT` (0.5) × the frame's world scroll, so the screen-static player and chaser trail streaming off behind them while obstacles (moving at full world speed) leave a trail lagging to their right; stamps are short-lived pooled state, so `?t=` seeks need no special handling, and stamps already dropped fade out naturally when the section ends; a per-section `beatFlash` boolean (default on in `NORMAL`, still gated behind `BEAT_SYNC_START_MS`, colour/alpha follow `lights`; a per-section `dance` field (its own flag; `true` or `'combo'`) makes the main camera "crazy dance" — with `true`: every 1/`DANCE_STEPS_PER_BEAT` beats from the section start it snaps (ease-out over `DANCE_SNAP_MS`) to a pseudo-random left/right tilt between `DANCE_TILT_MIN_DEG` and `DANCE_TILT_MAX_DEG` and, with its side rolled separately, a left/right slide of the camera scroll between `DANCE_SHIFT_MIN_PX` and `DANCE_SHIFT_MAX_PX` — the pure `dancePose(section, songMs, beatMs, runSeed)` in `src/cameraDance.js` returns `{ rotation, x, y }` from a deterministic hash of song time and a `runSeed` that `GameScene` rolls once per `create()` (`this.danceSeed`), so every run and restart dances differently while staying stateless from song time within a run (`?t=` safe); with `'combo'` it is the `true` dance plus a small head shake around the held pose from `DANCE_COMBO_START` of the way through each step — `DANCE_COMBO_SWINGS` shrinking swings of up to `DANCE_COMBO_TILT_DEG` (leaning further first, the slide following by `DANCE_COMBO_SHIFT_PX`), settling back onto the pose before the next snap; `dancePose` also returns the base `zoom`; in every mode the tilt adds to the `rotate` spin, the base zoom becomes `DANCE_ZOOM` (unless `rotate` is on) so tilted corners crop less, the zoom punch multiplies on top and the ghost cameras follow the camera's scroll; a per-section `jitter` boolean (its own flag, independent of `dance`; `final_highlight2` sets both, so each dance snap lands with a shake) shakes the main camera's scroll: every 1/`JITTER_KICKS_PER_BEAT` beats from the section start a kick offsets it by up to `JITTER_PX` per axis, re-rolled every `JITTER_REROLL_MS` and decaying to nothing over `JITTER_DECAY_MS` — the pure `jitterOffset(section, songMs, beatMs, runSeed)` in `src/cameraJitter.js` returns `{ x, y }` from the same hash and per-run seed as the dance, and `GameScene` adds it to the dance's slide, so it composes with `dance`, `rotate`, the zoom punch and the ghost cameras; the HUD tilts with the camera like under `rotate` but does not shake (scroll factor 0); a per-section `zoomPush: { every, amount }` (its own flag, independent of the others) is a zoom pump: counting beats from the section start in cycles of `every`, the zoom rises from 1 to 1 + `amount` (ease-in quad) over the last `ZOOM_PUSH_IN_FRACTION` of each cycle, peaking on the beat, then eases back out (ease-out quad) to 1 over the rest; cycle 0's out-phase stays at 1 so nothing jumps on entry, and the last in-phase snaps back to 1 at the section end — the pure `pushZoom(section, songMs, beatMs)` in `src/cameraPush.js` returns the multiplier and `GameScene` multiplies it onto the zoom punch, so it composes with dance, jitter, zoomPunch, rotate and the ghost cameras (`final_highlight2` pumps +25% every beat). A per-section `bikes` field (its own flag, independent of the others; `highlight1` sets `'grip'`, the following `highlight1b` `true` — the row drifts on across the split since only truthiness gates it) shows the `SpinBikes` rider row in the scenery strip, drifting left with the backdrop. Times are authored in ms and must sit on a real track beat — `tools/check-beats.js` (`yarn check:beats`, `--fix` rewrites, runs as `prebuild`) enforces it; each effect is gated on section song-time, never on another system's runtime state (enemy ramp, beat-sync gate stay independent).
